# Listen & Tabellen (Teil 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dichte Arbeitslisten nach L-01–L-12 (Kennung zuerst, Zahlen rechts, Status als Text, sticky Kopf, sichtbare Filter, Arbeits-Sortierung, drei Leer-Zustände, Laden ohne Flackern, Tastatur, Mehrfachauswahl, beschriftete Zeilenaktion, sichtbare Menge), ein Laufzettel-Beispiel und die Regeln im Handbuch.

**Architecture:** Neue Komponenten unter `components/table/`. `DataTable` ist kontrolliert (Sortierung, Auswahl, Markierung als Props + Callbacks); Filter und Blättern sind eigene Komponenten. Das Beispiel nutzt den In-Memory-Router aus `components/nav/examples/router.tsx` und hält den ganzen Listenzustand in der URL.

**Tech Stack:** wie Teil 1/2 (React 19, Tailwind 4 Tokens, lucide, Vitest + happy-dom + user-event, Storybook 10).

**Spec:** `docs/superpowers/specs/2026-10-26-tables-design.md`

## Global Constraints

- Nur Tokens aus `app/tokens.css`; Guard-Test gilt.
- Beide Dichten; Hell/Dunkel.
- Regeltexte Deutsch; Code Englisch.
- Links über `NavLink` (`components/nav/NavLink.tsx`); Kürzel über `useShortcut` (`components/nav/shortcuts.ts`).
- Nichts nur bei Hover; jede Icon-Aktion hat einen zugänglichen Namen.
- Datum `TT.MM.JJJJ`, Tausender `’`, leer = `—`.
- localStorage-Zugriffe in try/catch.

### Task 1: format, EmptyState, Pagination

**Interfaces (Produces):**
- `EMPTY = "—"`, `formatNumber(n: number | null | undefined): string` (`1234567 → "1’234’567"`, null → `EMPTY`), `formatDate(iso: string | null | undefined): string` (`"2026-10-21" → "21.10.2026"`).
- `EmptyState({ kind: "none" | "no-results" | "error", title, action?: React.ReactNode })` – `role="status"` (error: `role="alert"`), Icon je Art.
- `Pagination({ page, pageSize, total, onPageChange, onPageSizeChange, sizes = [25, 50, 100] })` – Text „{from}–{to} von {total}“ (`total=0` → „0 Einträge“), Knöpfe „Vorherige Seite“/„Nächste Seite“ disabled am Rand, Seitengrösse als natives `<select aria-label="Pro Seite">`.
- `usePageSize(listKey: string, fallback = 25): [number, (n: number) => void]` – localStorage `table:page-size:{listKey}`.
- Tests: Format-Fälle; EmptyState-Rollen; Pagination-Text „26–50 von 312“, Rand-Disable, Callbacks; usePageSize merkt sich Wert über Remount, überlebt werfendes localStorage.

### Task 2: ActionMenu

- `ActionMenu({ label = "Weitere Aktionen", items: { id; label; onSelect; disabled? }[] })` – Knopf mit `aria-haspopup="menu"`, `aria-expanded`; Menü `role="menu"`, Einträge `role="menuitem"`; öffnet mit Klick/Enter/↓ (Fokus erster Eintrag), ↑/↓/Home/End bewegen, Enter wählt, Escape schliesst und gibt Fokus an Knopf, Klick ausserhalb schliesst; Tab schliesst.
- Tests: Öffnen setzt Fokus; ↓ bewegt; Enter ruft `onSelect` und schliesst; Escape → Fokus auf Knopf.

### Task 3: FilterBar

- `type FilterField = { id: string; label: string; options: { value: string; label: string }[] }`
- `type ActiveFilter = { field: string; value: string }`
- `FilterBar({ fields, active, onChange, total, filteredTotal, noun })` – Trefferzahl „{filteredTotal} von {total} {noun}“ wenn gefiltert, sonst „{total} {noun}“ (`aria-live="polite"`); Chip „{Feld}: {Wert}“ mit Knopf „Filter {Feld}: {Wert} entfernen“; „Alle zurücksetzen“ ab zwei Filtern; „+ Filter“ öffnet Popover mit zwei nativen Selects („Feld“, „Wert“) und „Hinzufügen“; ein Feld kann mehrere Werte haben (je Chip), doppelte werden ignoriert.
- Tests: Chips sichtbar und entfernbar; Reset nur ab 2; Zähltext beider Formen; Hinzufügen fügt Chip hinzu.

### Task 4: DataTable – Lesen, Sortieren, Laden

**Interfaces (Produces):**
- `type Column<T> = { id: string; header: string; cell: (row: T) => React.ReactNode; align?: "left" | "right"; width?: string; sortable?: boolean; truncate?: boolean; title?: (row: T) => string }`
- `type Sort = { id: string; dir: "asc" | "desc" } | null`
- `DataTable<T>({ columns, rows, getRowId, getRowHref?, sort, onSortChange, status: "loading" | "ready" | "reloading", label, stickyFirst = true, ... })`; erste Spalte (`columns[0]`) wird als `NavLink` auf `getRowHref` gerendert, wenn gesetzt.
- Verhalten: `<table aria-label>` in `overflow-auto`-Container; `thead th` sticky top; erste Datenspalte sticky left wenn `stickyFirst`; `align: "right"` → `text-right tabular-nums`; `truncate` → `max-w`, `truncate`, `title`; Sortkopf als `<button>` im `th` mit `aria-sort` am `th`; Klickfolge asc → desc → `null`; `status="loading"` → 8 Skeleton-Zeilen (`aria-hidden`), `reloading` → Zeilen bleiben, `opacity-60`, Fortschrittsbalken, Tabelle `aria-busy="true"`; Zeilenklick (auf `tr`, nur wenn Ziel nicht in `a, button, input, [role=menu]`) ruft `onOpenRow(id)`.
- Tests: Rechtsbündigkeit; Truncate + title (Review Focus 5); Sortfolge + aria-sort; Skeleton bei loading; reloading behält Zeilen + aria-busy; Zeilenklick öffnet, Klick auf Link/Knopf/Checkbox nicht (Review Focus 3).

### Task 5: DataTable – Tastatur, Auswahl, Zeilenaktionen, BulkBar

- Zusätzliche Props: `cursorId`, `onCursorChange`, `onOpenRow(id)`, `selected: Set<string>`, `onSelectedChange`, `rowAction?: (row) => { label; icon?; onSelect }`, `rowMenu?: (row) => MenuItem[]`.
- Kürzel über `useShortcut`: `j`/`k` bewegen `cursorId` (Start: erste Zeile), `Enter` öffnet Cursor-Zeile (`onOpenRow`), `x` togglet Auswahl der Cursor-Zeile; markierte Zeile `data-cursor="true"` + Ring, `scrollIntoView({ block: "nearest" })`. Enter nur, wenn Fokus nicht in Eingabe/Knopf/Link (eigene Prüfung).
- Auswahl: Checkbox-Spalte vorn („{Kennung} auswählen“), Kopf-Checkbox „Alle auf dieser Seite auswählen“ mit `indeterminate`.
- `BulkBar({ count, hiddenCount, actions: { label; onSelect }[], onClear })` – „{count} ausgewählt“ + „· {hiddenCount} nicht sichtbar“ wenn > 0, `role="region" aria-label="Auswahl"`.
- Zeilenaktion: sichtbarer Knopf mit Text; `ActionMenu` daneben.
- Tests: j/k/x/Enter; Kürzel im Suchfeld wirkungslos (Review Focus 4); Kopf-Checkbox Teilzustand; BulkBar Texte; Zeilenaktion ruft Callback, öffnet Zeile nicht.

### Task 6: Beispiel Laufzettel-Liste

- `slips.ts`: `SLIPS` (~300, deterministisch), `STATIONS`, `URGENCY` (Reihenfolge Dringend > Hoch > Normal > Niedrig), `querySlips({ filters, q, sort, page, pageSize }) => { rows, total, filteredTotal }`; Standard-Sortierung Dringlichkeit desc, Eingipsdatum asc.
- `SlipList({ initial?, loader? })` – `MemoryRouter` + `LinkProvider`; URL-Parameter `f` (wiederholt, `feld:wert`), `q`, `sort` (`id:dir`), `page`, `size`; `loader(params) => Promise<Result>` (Standard: `querySlips` mit 300–600 ms Verzögerung, deterministisch nach Parametern); Request-Zähler verwirft veraltete Antworten; erster Ladevorgang `loading`, danach `reloading`; Fehler beim Nachladen → Zeilen bleiben, Fehlermeldung mit „Erneut versuchen“.
- Auswahl liegt im State, nicht in der URL; Filterwechsel leert sie; Blättern nicht.
- Leere Zustände: `variant="empty"` (Story) → „none“; Filter ohne Treffer → „no-results“ mit „Filter zurücksetzen“.
- Aktionen: Drucken (Zeile und Sammel), „Station setzen …“, „Zum Auftrag“ → Meldung `role="status"` („3 Laufzettel zum Drucken gesendet“).
- Story `Listen/Beispiel: Laufzettel` mit Varianten Standard, Leer, Fehler beim Nachladen.
- Tests: Standard-Sortierung (erste Zeile Dringend); Filter-Chip → URL + Zähltext; Auswahl über Seiten + Filter (Review Focus 1); veraltete Antwort (Review Focus 2, `loader` als Test-Double mit kontrollierten Promises); Keine-Treffer-Zustand + Reset.
