# Status & Lebenszyklus (Teil 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Einheitliche Status-Sprache, erlaubte Übergänge, Scan mit eindeutiger Rückmeldung, Durchlauf und lesbarer Verlauf nach S-01–S-12, ein Laufzettel-Durchlauf-Beispiel und die Regeln im Handbuch.

**Architecture:** Neue Komponenten unter `components/status/`. Reine Logik (Workflow, Ableitung, Zeitformate, Scan-Entscheid, Verlaufs-Gruppierung) in `.ts`-Dateien ohne React, damit Nova sie 1:1 nachbauen kann; Komponenten sind kontrolliert und bekommen `now` als Prop. Das Beispiel nutzt den In-Memory-Router aus Teil 2.

**Tech Stack:** wie Teil 1–3 (React 19, Tailwind 4 Tokens, lucide, Vitest + happy-dom + user-event, Storybook 10).

**Spec:** `docs/superpowers/specs/2026-10-26-status-design.md`

## Global Constraints

- Nur Tokens aus `app/tokens.css`; Guard-Test gilt.
- Beide Dichten; Hell/Dunkel.
- Regeltexte Deutsch; Code Englisch.
- Links über `NavLink`; Kürzel über `useShortcut`.
- Nichts nur über Farbe; Icons `aria-hidden`, Bedeutung im Text.
- Datum `TT.MM.JJJJ`, Datum+Zeit `TT.MM.JJJJ HH:MM`, Dauer „2 h 10 min“ / „45 min“ / „3 d 4 h“.
- Rückgängig 8 s; Doppel-Scan-Sperre 3 s; Verlaufs-Gruppierung 5 min; Kurzverlauf 3 Einträge.

## Review Focus

1. **Scan beim gesperrten Zettel:** Fertig/Storniert gescannt → Fehlermeldung „… ist storniert“, kein Ortswechsel, kein Eintrag. → Test Task 3.
2. **Rückgängig nach Ablauf / nach weiterem Wechsel:** Rückgängig erscheint nur für den letzten Wechsel; ein neuer Wechsel ersetzt die Meldung. → Test Task 6.
3. **Doppel-Scan verschiedener Codes:** Code A, dann Code B innerhalb 3 s → beide werden verarbeitet (Sperre gilt pro Code). → Test Task 3.
4. **Verlaufs-Gruppe über Personen:** Feldänderungen von zwei Personen innerhalb 5 min werden nicht zusammengefasst; Statuswechsel nie gruppiert. → Test Task 5.
5. **Dialog-Abbruch stellt Fokus zurück:** Escape/Abbrechen in der Storno-Bestätigung → Fokus zurück auf den auslösenden Knopf, Status unverändert. → Test Task 2.

### Task 1: workflow, time, StatusBadge

**Interfaces (Produces):**
- `type StatusCategory = "planned" | "active" | "waiting" | "done" | "canceled"`
- `type StatusDef = { id: string; label: string; category: StatusCategory }`
- `type Transition = { from: string; to: string; verb: string; confirm?: boolean; reason?: "required" | "optional"; primary?: boolean; when?: (ctx) => string | null }` (`when` gibt Grund zurück, warum gerade nicht möglich, sonst `null`)
- `type Workflow<C = unknown> = { statuses: StatusDef[]; transitions: Transition[] }`
- `statusOf(wf, id): StatusDef`; `allowedTransitions(wf, from, ctx): { transition; blocked: string | null }[]` (nur `from`-passende; `blocked` aus `when`)
- `deriveStatus(parts: StatusCategory[]): { category: StatusCategory; done: number; total: number }` – Regeln: alle planned → planned; alle canceled → canceled; alle done|canceled und ≥1 done → done; sonst active; `done` zählt done+canceled.
- `time.ts`: `formatDuration(ms)` („45 min“, „2 h 10 min“, „3 d 4 h“, <1 min → „< 1 min“), `formatDateTime(ms)` → „21.10.2026 14:05“, `formatRelative(ms, now)` → „gerade eben“ (<1 min), „vor 5 min“, „vor 3 h“ (gleicher Tag), sonst „gestern 14:05“, sonst „21.10.2026“.
- `StatusBadge({ status: StatusDef; since?: number; now?: number; overdue?: string })` – Icon je Kategorie (Circle, CircleDot, CirclePause, CircleCheck, CircleX; `aria-hidden`), Text, `data-category`; mit `since` „· seit {formatDuration(now-since)}“ und `title={formatDateTime(since)}`; `overdue` → zusätzlicher Warn-Text mit AlertTriangle.
- Tests: Ableitung alle vier Fälle + Zählung; allowedTransitions filtert `from` und liefert `blocked`; Zeitformate Grenzfälle (59 s, 130 min, 76 h, gestern, älter); Badge Text/Kategorie/seit/title/overdue.

### Task 2: StatusMenu, ConfirmDialog, UndoNotice

- `ActionMenu` erweitern: optionales `trigger?: React.ReactNode` (Inhalt des Knopfs, Standard „…“-Icon) und `triggerRef?`/`open`-Steuerung nur falls nötig; bestehende Tests bleiben grün.
- `StatusMenu({ workflow, current, ctx, onSelect(t: Transition), shortcut = true })` – Knopf zeigt `StatusBadge` + Chevron, `aria-label="Status ändern: {label}"`; Menü-Einträge = `allowedTransitions` mit `verb`; blockierte erscheinen `aria-disabled` mit Grund als zweiter Zeile (S-05: Grund sichtbar); `S` öffnet (useShortcut, nicht in Eingaben).
- `ConfirmDialog({ open, title, consequences: string[], confirmLabel, reason?: "required" | "optional", reasonLabel = "Grund", onConfirm(reason?: string), onCancel, tone = "danger" })` – `role="alertdialog"`, `aria-modal`, Portal, Fokus startet auf „Abbrechen“, Tab-Falle, Escape = Abbrechen, Fokus zurück auf vorher fokussiertes Element; Pflichtgrund leer → Bestätigen-Klick zeigt Feldfehler „Bitte einen Grund angeben“ (F-03) statt zu bestätigen.
- `UndoNotice({ message, onUndo, onClose, duration = 8000 })` – `role="status"`, Knopf „Rückgängig“, schliesst nach `duration` (`onClose`); neuer `message`-Key startet Timer neu.
- Tests: Menü nur erlaubte + blockierter Grund; `S` öffnet, im Input nicht; Dialog Fokus/Tab/Escape/Pflichtgrund/Fokus-Rückgabe (Review Focus 5); Undo ruft Callback, schliesst nach 8 s (fake timers).

### Task 3: scan, ScanField, LockedNotice

- `scan.ts`: `type ScanTarget = { code: string; label: string; station: string | null; locked: string | null; visits: { station: string }[] }`; `resolveScan({ code, station, targets, lastScans: Map<string, number>, now, dedupeMs = 3000 }) => { kind: "in" | "out" | "duplicate" | "unknown" | "locked"; target?; visit?: number; message: string }`
  - Code normalisieren: trim, Gedankenstrich/Bindestrich/Leerzeichen egal (wie `identifier.ts` aus Teil 2 – wiederverwenden).
  - `duplicate`: derselbe normalisierte Code innerhalb `dedupeMs` → „Schon erfasst: {label}“.
  - `unknown` → „Unbekannter Code: {roher Code}“; `locked` → „{label} ist {locked}. Kein Scan möglich.“
  - Liegt an `station` → `out` „{label} ausgescannt aus {Station}“; sonst `in` „{label} eingescannt in {Station}“ + bei `visit ≥ 2` „ ({visit}. Durchlauf)“.
- `ScanField({ station, stationLabel, onScan(result), resolve })` – Feld `aria-label="Code scannen"`, Enter löst aus, leert Feld, behält Fokus; Rückmeldung gross mit Icon, `role="status"` (in/out/duplicate) bzw. `role="alert"` (unknown/locked).
- `LockedNotice({ status: StatusDef; at: number; by: string; reason?: string; canReopen: boolean; reopenHint?: string; onReopen })` – Satz „{label} am {Datum} von {by}: {reason}. Felder sind gesperrt.“; „Wieder öffnen“ oder Hinweis.
- Tests: in/out/2. Durchlauf/unknown mit Code/locked (Review Focus 1)/duplicate in 3 s, gültig nach 3 s/verschiedene Codes nicht gesperrt (Review Focus 3); ScanField Enter, leert, Rollen; LockedNotice beide Varianten.

### Task 4: RouteTimeline

- `type Visit = { station: string; label: string; in: number; out: number | null; norm?: number }` (ms)
- `RouteTimeline({ visits, now })` – `<ol aria-label="Durchlauf">`, je Besuch Station, „{n}. Durchlauf“ ab dem zweiten, Ein/Aus als `formatDateTime`, Dauer; offener Besuch „jetzt hier“ + laufende Dauer + `aria-current="step"`; Dauer > `norm` → „Länger als üblich (Richtzeit {formatDuration(norm)})“; leer → „Noch nicht eingescannt“.
- Tests: Reihenfolge, 2. Durchlauf, jetzt hier, Richtzeit, leer.

### Task 5: activity, ActivityLog

- `type ActivityEntry = { id: string; at: number; actor: string; via: "hand" | "scan" | "system"; device?: string; kind: "status" | "location" | "field"; field?: string; from?: React.ReactNode | string; to?: React.ReactNode | string; text?: string }`
- `groupActivity(entries, windowMs = 5*60_000)` → neueste zuerst; aufeinanderfolgende `field`-Einträge derselben Person mit Abstand ≤ window zur jeweils vorherigen werden Gruppe `{ id; entries }`; `status`/`location` nie gruppiert (Review Focus 4).
- `ActivityLog({ entries, now, filter?: "all" | "status" | "fields", onFilterChange?, limit?, moreHref? })` – Sätze: Feld „{actor} hat {field} von {from} auf {to} geändert“, Status „{actor} hat Status auf {Badge} gesetzt“, Ort „{label}“-Text aus `text`; Scan-Einträge „per Scan ({device})“; Zeit `formatRelative` mit `title`; Gruppe „{actor} hat {n} Felder geändert“ als Disclosure-Knopf (`aria-expanded`); Filter als `ViewFilter` aus Teil 2 oder Segment mit `aria-pressed`; `limit` zeigt Kurzform + Link „Ganzer Verlauf“.
- Tests: Satzform, gruppiert 3 in 5 min, trennt bei 6 min, nicht über Personen, Status nie gruppiert, Filter, limit 3 + Link.

### Task 6: Beispiel Laufzettel-Durchlauf

- `slip.ts`: `SLIP_WORKFLOW` (Spec-Tabelle; `fertig` hat `when: ctx => ctx.atStation ? "Fertig melden geht erst nach dem Ausscannen" : null`, `primary: true`; `storniert` `confirm: true, reason: "required"`; Wieder öffnen `from: fertig|storniert → in-arbeit`); `STATIONS` mit `norm` (3D 6 h, Guss 4 h, Polissage 8 h, Versand 2 h); Auftrag `26100013` mit 4 Zetteln (Seed: 1/4 in Arbeit an Guss seit 5 h; 2/4 fertig; 3/4 offen; 4/4 zurückgestellt); `applyEvent(state, event, now)` reiner Reducer für `scan` / `transition` / `undo`, schreibt Verlaufseinträge (S-09: Undo = neuer Eintrag).
- `SlipDetail({ initial?: "default" | "canceled" | "done-locked", now? })` – Router-Pfade `/laufzettel/:id` (+ `?tab=details|durchlauf|verlauf&verlauf=all|status|fields`); PageHeader mit Kennung, Badge (Stand, seit), Ort („An Station Guss · seit …“ / „Unterwegs, zuletzt Guss“), Primärknopf + blockierter Grund als Text, StatusMenu; Tabs; Details-Felder (`readOnly` wenn gesperrt) + Kurzverlauf + Auftragskarte (`deriveStatus`, Links auf Zettel); Scan-Bereich mit Stationsauswahl + ScanField; ConfirmDialog für Storno; UndoNotice nach jedem nicht bestätigten Wechsel.
- Uhr: `now`-Prop (Story fest auf `2026-10-26T14:00`), Wechsel setzen Zeit = aktuelles `now` + vergangene Sekunden seit Mount (oder einfach `Date.now()`-Offset); Tests geben `now` fest.
- Story `Status/Beispiel: Laufzettel-Durchlauf`: Standard, Storniert, Fertig (darf nicht öffnen).
- Tests: Scan Zettel 3/4 an Guss → „In Arbeit“ + Verlaufseintrag; Fertig melden an Station blockiert mit Grund, nach Ausscannen möglich; Stornieren → Dialog, Grund Pflicht, danach LockedNotice + Felder readonly; Rückgängig stellt Stand her + Eintrag; neuer Wechsel ersetzt Undo (Review Focus 2); Auftragskarte zeigt „1 von 4 … erledigt“ → nach Fertig „2 von 4“.
